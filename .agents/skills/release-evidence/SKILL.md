# Release verification

1. Read one `CG-*` story and its release README; preserve existing story IDs and completed evidence.
2. Write scoped observable acceptance criteria only for work the user approved; avoid overlapping stories.
3. Record exact commands, actual test/build results, browser checks and their limits. Never report unrun CI or screenshots as passing.
4. Keep planned and implemented state separate; update README/docs indexes only when the affected claim changes.
5. Review the diff and ask for commit approval separately from implementation approval; do not start the next story automatically.
